# Prime Sales Performance – Power BI project

A Power BI project (PBIP) that reproduces the **Prime Sales Performance** dashboard from the
reference screenshot as page 1, and adds four analyst pages (target and forecast, KAM analysis,
product and portability, data quality) on a proper star-schema model with 75 DAX measures.

> **Dummy data.** Everything in `data/` is placeholder data generated by
> `tools/generate_sample_data.py`. The September 2026 slice is calibrated so page 1 reconciles to
> the reference screenshot; July and August are synthetic history. Replace the workbook with the
> real extract before using any number.

## Folder layout

| Path | What it is |

| `PrimeSalesPerformance.SemanticModel/` | Semantic model in TMDL: tables, relationships, Power Query (M) partitions, measures. |
| `PrimeSalesPerformance.Report/` | Report in PBIR: five pages, 101 visuals, custom theme. |
| `data/PrimeSales_SampleData.xlsx` | Source workbook (Excel tables `Fact_Activations`, `Dim_KAM`, `Dim_Product`, `Dim_Target`). |
| `data/csv/` | Same tables as CSV. |
| `dax/measures.dax` | All measures as plain DAX (for copy/paste or Tabular Editor). |
| `theme/PrimeSalesTheme.json` | Report theme (green/red, title bars, matrix headers). Importable into any report. |
| `docs/DATA_DICTIONARY.md` | Column and measure definitions, assumptions to confirm. |
| `tools/generate_sample_data.py` | Regenerates the dummy workbook and CSVs. |
| `tools/build_pbip.py` | Generates the whole PBIP (model + report + theme + DAX file) from one spec. |
| `tools/validate_pbir.py` | Validates every report JSON file against Microsoft's published PBIR schemas. |

## Open it (5 minutes)

1. **Power BI Desktop** (May 2024 or later). In *File > Options and settings > Options > Preview
   features* enable **Power BI Project (.pbip) save option**, **Store semantic model using TMDL
   format** and **Store reports using enhanced metadata format (PBIR)**. Restart Desktop.
2. Copy `data/PrimeSales_SampleData.xlsx` somewhere local, e.g. `C:\PrimeSales\`.
3. Open `PrimeSalesPerformance.pbip`. When prompted, edit the **DataFile** parameter
   (*Transform data > Edit parameters*) to the full path of the workbook, or change the default in
   `PrimeSalesPerformance.SemanticModel/definition/expressions.tmdl` before opening.
4. **Refresh**. Page 1 should show 4,515 points / 2,347 QTY in the matrix total, the 547 → 130
   daily series and Asim Mamoon at 1,934 points, i.e. the reference numbers.
5. Save. Desktop will add its own local cache files (`.pbi/`), which are git-ignored.

To point at real data, replace the rows inside the four Excel tables (keep the column names and
types listed in `docs/DATA_DICTIONARY.md`), or repoint the M partitions at the real source (SQL,
Dataverse, SharePoint). Only the four `Excel.Workbook` partitions need to change.

## Pages

| # | Page | Management question it answers |
| --- | --- | --- |
| 1 | **Overview** (replica) | Where are points and activations coming from this month, by director, product and seller? Filtered to the latest month in the data. |
| 2 | **Target & Forecast** | Are we on track? Points MTD vs prorated target, gap, required daily run-rate, linear run-rate forecast, cumulative actual vs target line, gauge, director actual vs target, seller scorecard with RAG status. |
| 3 | **KAM Analysis** | Who is carrying the number? Top N slicer, metric selector (Points / VOA / MNP / Achievement %), volume-vs-points scatter (bubble = MNP), 100 % product mix per seller, full ranking table with rank, contribution, MNP share, last activation and idle days. |
| 4 | **Product & Portability** | What is the mix doing? MNP share of GSM, FNP share of fixed, fiber share, daily VOA by product group, product matrix with month-over-month (same day-range), decomposition tree (Director > TL > KAM > Product group > Product), seller × day activation heatmap. |
| 5 | **Data Quality** | Can the numbers be trusted? Duplicate IDs, unmapped sellers/products, zero-point eligible rows, future-dated rows, exception list, seller inactivity, monthly reconciliation totals. |

Every page shares the header: Director and Team Leader slicers (left), Month slicer, refresh
timestamp (`T: dd MMM yyyy - hh:mm`) and a **DUMMY DATA** flag (right). Remove the flag textbox
once real data is connected.

## Model

```
Dim_Date ──┐
Dim_KAM ───┼──< Fact_Activations (1 row per activated line)
Dim_Product┘
Dim_KAM ───┬──< Dim_Target (1 row per seller per month)
Dim_Date ──┘
_Measures            all DAX measures, in display folders 01 Core … 07 Labels
Metric Selector      field parameter (Points / VOA / MNP VOA / Achievement %)
Top N                {5,10,15,20,25,30,50} for the Top N slicer
Last_Refresh         DateTime.LocalNow() captured at refresh
```

Key definitions (confirm against the official e& definitions before publishing):

- **VOA** = volume of activations = `SUM(Quantity)`.
- **QTY** in the matrix = points-eligible activations (`PointsEligible = TRUE`). This is why the
  reference shows Mobile VOA 2,115 but QTY 2,096.
- **Achievement % (To Date)** = points ÷ (full-month target × days elapsed ÷ days in month).
- **Points Forecast (Run-Rate)** = points to date + daily run-rate × days remaining. Linear; no
  seasonality. Treat as a directional indicator, not a commitment.
- **Prev Month Same Period** compares day 1 to the as-of day of both months.
- **As-Of Date** = latest activation date in the fact table. Switch to `TODAY()` in
  `_Measures[As-Of Date]` once the extract is refreshed daily.

## Regenerate or extend

```bash
pip install openpyxl jsonschema referencing
python3 tools/generate_sample_data.py     # rebuild dummy data (deterministic seed)
python3 tools/build_pbip.py               # rebuild model + report + theme + dax/measures.dax
python3 tools/validate_pbir.py            # schema-check every report file (downloads schemas once)
```

`build_pbip.py` is the single source of truth: add a measure to `MEASURES`, or a visual to one of
the `page_*()` functions, and rerun. It rejects overlapping or off-canvas visuals.

## Known limitations

- Built and schema-validated from code, not yet opened in Power BI Desktop on this branch. If
  Desktop reports a visual it cannot render, delete that visual and rebuild it from the field
  list using the mapping in `docs/DATA_DICTIONARY.md`; the model and measures are unaffected.
- The reference header uses a green-to-red gradient; PBIR shapes are solid, so the header is
  solid green with a red accent line. Use a background image if the gradient is required.
- Colours are approximated from the screenshot. Replace `theme/PrimeSalesTheme.json` with the
  approved e& palette when available.
- Sellers are placeholders (`KAM 01` … `KAM 18`); the three director labels come from the
  reference. Targets are dummy (August actual × 1.10 for September).
