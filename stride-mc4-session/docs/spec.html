Summary

The current app never enforced capacity: the Submit button's formula referenced a list that does not exist (Stride MC5 Registration) and two undefined variables, so the button compiled with errors and did nothing. Registrations were only saved through the form's default behaviour with no checks at all.

Submit validation – order of checks

The same sequence runs in both tiers; v2 adds the edit path and the post-save guard. Order matters: cheap checks first, the write last.

Set(varSegment, Trim(cmbSegment.Selected.Value));
Set(varSession, Trim(cmbSession.Selected.SessionDate));
Set(varIsPB,    varSegment = fxPBSegmentValue);          // "PB"
Set(varCapacity, If(varIsPB, fxPBCapacity, fxSMBCapacity)); // 8 : 28

Refresh('Stride MC4 Registration');
Set(varBooked, If(varIsPB,
    CountRows(Filter('Stride MC4 Registration', Date.Value = varSession, Segment.Value = varSegment)),
    CountRows(Filter('Stride MC4 Registration', Date.Value = varSession))));
Set(varExisting, LookUp('Stride MC4 Registration', Email = varEmail || 'Employee Name'.Email = varEmail));

If(
    !fxRegistrationOpen,                        Notify("Registration is closed.", Error),
    IsBlank(varSegment) || IsBlank(varSession), Notify("Please select ...", Warning),
    !varEditMode && !IsBlank(varExisting),      Notify("... already registered for " & varExisting.Date.Value, Warning),
    varBooked >= varCapacity,                   Notify("The selected session is full. Please choose another date.", Error),
    IfError(
        Set(varSaved, Patch('Stride MC4 Registration', Defaults(...), { ... })),
        Notify("Registration could not be saved: " & FirstError.Message, Error),
        /* re-count; if varBookedAfter > varCapacity → Remove(varSaved) and show the full message */
        /* else success toast, reload colReg / colAvailability, refresh varMyReg */
    )

Risks and decisions for you

  • Confirm the 28-seat interpretation (shared per date vs per segment). One-line change either way.
  • Confirm the PB choice value is exactly PB. The rule keys on it via fxPBSegmentValue.
  • Atomic capacity needs a Power Automate flow on item creation if sessions routinely fill in the last minutes; the v2 post-save guard covers the realistic case.
  • Confirmation email is not wired. Outlook is already connected; add Office365Outlook.SendEmailV2 after the success toast once sender and wording are approved.
  • Visibility: the availability screen lists registrant names to all users. Gate it behind a coordinator group if that is sensitive.
  • Branding: colours reuse the app's existing burgundy palette; swap the tokens in App.Formulas for the approved e& values and add the logo media file.
